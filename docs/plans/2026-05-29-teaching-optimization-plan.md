# 教学能力优化计划

更新时间：2026-06-09
状态：部分实施（P0 错题反馈回流已完成；P1 情绪感知调整、P2 前置节点关联已部分接入 tutor prompt；讲解字数已从 80-150 字升级为 650-1000 字；剩余：间隔复习、测试题对齐讲解、教学效果追踪）

## 1. 当前教学流程概览

```
评估 → 用户画像 → 学习路径生成 → 选择节点 → 加载节点内容
  → Tutor 讲解（策略：explain/analogy/stepbystep/socratic）
  → 课后停顿：追问 / 进入小测
  → 客观题测试
  → 通过 → 下一节点
  → 未通过 → 错题讲解 → 变式题 → 重测
```

## 2. 当前问题分析

### 2.1 策略切换是机械轮转，不是教学诊断

当前策略选择：
```python
_STRATEGY_MAP = {
    0: "explain",      # 首次
    1: "analogy",      # 第2次
    2: "stepbystep",   # 第3次
    3: "socratic",     # 第4次+
}
```

问题：不管学生错在哪里，只要重试就换策略。学生可能只是粗心算错，不需要换类比法。

### 2.2 错题反馈没有回流到教学

`wrong_question_explanations` 里有详细的错因分析（错选了什么、正确答案为什么对），但下次讲解时：
- `_select_strategy()` 只看 `attempt_count`，不看错因
- `_strategy_instruction()` 虽然接收 `feedback` 参数，但初始讲解时 feedback 为空
- 错题讲解和变式题环节与主讲解是分离的，没有形成闭环

### 2.3 情绪检测没有行动

`detect_affect()` 检测到情绪后只发了一个事件，教学行为没有任何调整：
- 检测到"困惑" → 应该降低难度、增加例子
- 检测到"焦虑" → 应该给鼓励、放慢节奏
- 检测到"自信" → 可以加快节奏、给挑战题

### 2.4 课后停顿的选择缺乏引导

当前课后停顿的提示是：
```
"这一步先讲到这里，接下来你可以自己决定是继续讲、换个例子、先总结，还是来一道题。"
```

问题：
- 给了 4 个选项但没有推荐
- 不根据讲解质量和学生表现给建议
- 学生不知道该选什么

### 2.5 节点间没有知识传递

每个节点的讲解是独立的：
- 学完"时域分析"后学"根轨迹"，不会关联前面的知识
- 没有"你已经掌握了 X，现在我们把它扩展到 Y"的过渡
- 前置节点的掌握情况没有进入当前节点的 prompt

### 2.6 测试题和讲解内容脱节

- 客观题由 `objective_test_generator` 生成，但不一定覆盖讲解中强调的重点
- 讲解中提到的"常见误区"不一定在测试中出现
- 变式题只针对错题本身，不针对错题背后的薄弱概念

## 3. 优化方案

### P0：错题反馈回流到教学（影响最大，改动最小）✅ 已实施 (2026-06-03)

**目标**：学生做错后，下一轮讲解能针对性地重讲错因。

**改动**：
1. 在 `tutor_node` 中，当 `attempt_count > 0` 时，读取 `wrong_question_explanations`
2. 提取错因摘要，注入 system prompt
3. `_select_strategy()` 改为同时考虑错因类型：
   - 概念混淆 → socratic（引导辨析）
   - 计算错误 → stepbystep（逐步检查）
   - 理解偏差 → analogy（换个类比）
   - 粗心/没看清 → explain（强调细节）

**涉及文件**：`nodes/tutor.py`

**预计**：1.5 小时

### P1：情绪感知教学调整 🔧 部分实施 (2026-06-03)

**目标**：检测到情绪信号后，调整教学行为。

**改动**：
1. 在 `_get_diff()` 或 system prompt 中加入情绪调整指令
2. 困惑 → 降低难度一档 + "让我换个方式说"
3. 焦虑 → "别急，这个确实不简单" + 简化表述
4. 自信 → 可以跳过基础，直接给进阶问题

**涉及文件**：`nodes/tutor.py`

**预计**：1 小时

### P1：智能课后推荐

**目标**：课后停顿时给一个推荐选项。

**改动**：
1. 在 `post_lesson_choice` 节点中，根据以下信号计算推荐：
   - 讲解轮数 > 2 → 推荐"进入小测"
   - 学生追问过 → 推荐"再讲一遍"
   - 讲解很短且学生没追问 → 推荐"进入小测"
2. 在 `pending_interaction_recommended` 中设置推荐值
3. 前端高亮推荐选项

**涉及文件**：`nodes/post_lesson_choice.py`、`nodes/tutor.py`、前端

**预计**：1.5 小时

### P2：节点间知识关联 🔧 部分实施 (2026-06-03)

**目标**：讲解新节点时，关联已掌握的前置节点。

**改动**：
1. 在 `tutor_node` 中，从 `knowledge_graph` 找当前节点的前置节点
2. 如果前置节点已 mastered，在 prompt 中加入：
   "学生已经掌握了【前置节点名称】，现在要从这个基础上扩展到【当前节点】"
3. 如果前置节点未 mastered，在 prompt 中加入：
   "学生对【前置节点名称】掌握不够，需要先简要回顾再进入新内容"

**涉及文件**：`nodes/tutor.py`

**预计**：1 小时

### P2：测试题与讲解重点对齐

**目标**：客观题覆盖讲解中强调的要点和误区。

**改动**：
1. 在 `objective_test_generator` 中，读取 `tutor_content` 提取讲解要点
2. 将要点作为出题约束注入 prompt
3. 确保至少 2 道题覆盖讲解中提到的"常见误区"

**涉及文件**：`nodes/objective_test.py`

**预计**：1.5 小时

### P3：教学效果追踪

**目标**：记录每次讲解的策略和效果，用于后续优化。

**改动**：
1. 在 StudentState 中新增 `teaching_episodes` 列表
2. 每次讲解记录：{node_id, strategy, attempt_count, outcome(pass/fail), affect}
3. 在 `_select_strategy()` 中参考历史效果
4. API: `GET /api/students/{id}/teaching-history`

**涉及文件**：`knowledge_map/student_state.py`、`nodes/tutor.py`

**预计**：2 小时

## 5. 不做的事

- 不重写整个教学 prompt 体系（当前 prompt 质量可以）
- 不引入复杂的学习者模型（保持轻量 JSON）
- 不做 A/B 测试框架（当前阶段不需要）
- 不做多轮对话记忆（每个节点独立讲解即可）

## 6. 验收标准

每个优化点的验收：
- 单元测试覆盖新逻辑
- 实际运行一个节点讲解，观察 LLM 输出是否符合预期
- 全量测试不破
