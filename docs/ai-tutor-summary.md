# AI Tutor 已完成改进详细说明

## 一、文档目的

这份文档只解释当前已经完成并可运行的能力，不按日期拆分。

重点说明三件事：

1. 三类知识图谱在系统中分别怎么用。
2. 向量库如何入库、检索、融合和回流到教学。
3. 改进项到底改了什么，为什么这么改，实际效果是什么。

---

## 二、系统现在的整体工作方式

当前系统是一个闭环学习流程，而不是普通问答机器人。

主链路已经升级为节点制掌握学习：

1. 主题识别与确认。
2. 学前诊断，确定学习起点。
3. `initial_node_selector` 从图谱 2.1 中选择初始节点。
4. `node_content_loader` 抽取当前节点学习目标、必会点、常见误区和证据上下文。
5. Tutor 优先覆盖图谱 2.1 当前节点材料，并用图谱 2.2 / RAG 做补充证据增强。
6. 讲解后进入显式选择：临时问题或开始测试。
7. 临时问题走图谱 2.2 检索回答，然后回到选择。
8. 节点后客观题批量测试，程序按 answer_key 确定性评分。
9. 未通过则错题讲解与变式题；通过则规划下一节点。
10. 用户选择继续下一节点或今天结束并生成作业。
11. 二次登录/恢复时根据学生状态和作业状态分流。

注释说明：
这里的核心变化是“有状态的持续教学 + 图谱节点推进”，不是“每次从零开始的一问一答”。

## 三、三类知识图谱的使用说明

### 1）课程知识图谱（课程主线图）

作用：定义课程结构和学习路径。

在系统中的用法：

1. 测评后定锚点：根据概念差距选出当前起始节点。
2. 讲解前提供上下文：前置知识、学习目标、常见误区、相邻节点。
3. 卡点时做诊断：前置缺口检测，判断是否需要先补基础。
4. 讲完后定去向：给出继续当前、补前置、转相关节点等选项。

改进效果：

1. 教学顺序从“模型自由发挥”变为“按课程结构推进”。
2. 遇到卡点时能解释为什么卡住，并给出明确补救路径。

注释说明：
课程图谱负责“主线与路径”，不是资料仓库。

### 2）补充知识图谱（上传资料形成的证据层）

作用：补充课程主资料里没有覆盖的场景、案例和企业文档。

在系统中的用法：

1. 文件上传后自动解析、切块、向量化、建索引。
2. 检索时与课程主库并行召回。
3. 融合时课程主库优先，补充库用于补位。
4. 支持单文件删除和整库清空，索引和向量同步更新。

改进效果：

1. 回答不再只依赖课程主资料。
2. 对个性化资料和企业上下文更友好。

注释说明：
补充知识负责“证据增强”，不负责改变课程学习主线。

### 3）用户知识图谱 UKG（用户学情图）

作用：记录每个用户在每个知识点的真实学习状态。

数据结构（核心字段）：

1. status：not_started、in_progress、mastered、skipped。
2. turn_count：该节点互动轮次。
3. calibrated：测评校准分。
4. gap_type：概念缺口类型。
5. id：节点标识。

状态流转规则：

1. 测评后初始化为 not_started（带 calibrated）。
2. Tutor 进入节点时转为 in_progress，轮次递增。
3. 触发掌握标记并通过门控校验后转为 mastered。
4. 用户或策略跳过时转为 skipped。

更新触发点：

1. 测评完成后初始化 UKG。
2. Tutor 每轮讲解写入当前节点状态。
3. 隐藏教学标记触发掌握/跳过更新。
4. 下一步决策读取 UKG 做路径推荐。

前端与恢复机制：

1. 通过 user_knowledge_graph.sync 同步全量或增量状态。
2. 通过 graph.node_update 同步当前节点变化。
3. 历史恢复时重建 UKG 相关事件，恢复学习状态而非仅聊天文本。

改进效果：

1. 系统知道用户“已经会什么、还不会什么、下一步该补什么”。
2. 同一用户跨轮次、跨会话可以连续学习。

注释说明：
UKG 是个性化教学的核心，不是展示数据。

## 四、向量库详细使用说明

### 1）库结构

当前使用双库策略：

1. course_primary：课程主资料库。
2. supplemental：用户上传资料库。

两者独立建库、独立索引、统一融合。

### 2）入库流程

1. 解析文件内容（PDF、Markdown、文本等）。
2. 切分为文档块并附加 metadata。
3. 写入对应向量集合。
4. 更新知识索引与 BM25 缓存。

注释说明：
课程主库长期稳定，补充库高频增删，设计上必须分离。

### 3）检索流程

1. 先解析图谱锚点，建立图谱上下文。
2. 优先在 course_primary 召回当前节点与相关节点证据。
3. 同步在 supplemental 召回补充证据。
4. 执行混合融合：向量召回 + BM25 + 元数据匹配。
5. 进行重排与去重，生成可引用证据清单。
6. 若本地证据不足且开关开启，触发外部搜索补证据。

注释说明：
检索不是“只看向量相似度”，而是“图谱优先 + 混合召回 + 证据可引用”。

### 4）资料管理接口

1. 列表：/api/knowledge/files
2. 上传：/api/upload
3. 删除单文件：/api/knowledge/files/{filename}
4. 清空补充库：/api/knowledge/files（DELETE）

注释说明：
这些接口只管理补充库，不会破坏课程主库。

## 五、端到端运行流程（带 UKG 与向量库）

1. 用户输入主题，系统做主题识别与确认。
2. 进入对话式测评，输出概念差距。
3. 初始化 UKG，确定图谱锚点。
4. Tutor 发起检索：图谱锚点驱动，课程主库优先，补充库补位。
5. 返回证据、图谱上下文、推荐下一步信息。
6. Tutor 按证据讲解，并同步更新 UKG 与图谱节点状态。
7. 系统基于 UKG 和图谱关系做下一步推荐。
8. 前端通过事件实时渲染状态；会话恢复时可回到原学习进度。

## 六、已完成改进项详细解释

### 改进 1：学习流程从单轮问答升级为状态机闭环

1. 做了什么：补齐 flow_status、assessment_state、pending_interaction 等流程状态。
2. 为什么做：避免每轮对话丢上下文。
3. 结果：能连续推进，不会反复从头开始。

### 改进 2：课程图谱从展示层升级为决策层

1. 做了什么：图谱锚点、前置缺口、后继路径、盲区检测进入决策。
2. 为什么做：把教学顺序和补救路径结构化。
3. 结果：系统可以解释“为什么下一步这样走”。

### 改进 3：UKG 从测评结果升级为持续演化学情图

1. 做了什么：定义 UKG 字段、状态流转和事件同步。
2. 为什么做：实现真正个性化教学。
3. 结果：系统可按用户掌握度动态调度，不是统一脚本。

### 改进 4：检索从单一召回升级为双库混合检索

1. 做了什么：course_primary + supplemental 双库，混合召回与重排。
2. 为什么做：同时保证主线正确性和场景覆盖度。
3. 结果：回答更稳、更贴题、可追溯证据更完整。

### 改进 5：会话恢复从文本恢复升级为学习状态恢复

1. 做了什么：恢复 UKG、图谱节点、测评状态、等待输入状态。
2. 为什么做：学习产品核心是“接着学”，不是“接着聊”。
3. 结果：中断后能无缝回到原学习阶段。
