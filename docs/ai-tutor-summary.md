# AI Tutor 已完成改进详细说明

## 一、文档目的

这份文档只解释当前已经完成并可运行的能力，不按日期拆分。

重点说明三件事：

1. 三类知识图谱在系统中分别怎么用。
2. 向量库如何入库、检索、融合和回流到教学。
3. 改进项到底改了什么，为什么这么改，实际效果是什么。

---

## 二、系统现在的整体工作方式

当前系统是一个闭环学习流程，而不是普通问答机器人。

主链路已经升级为节点制掌握学习：

1. 主题识别与确认。
2. 学前诊断，确定学习起点。
3. `initial_node_selector` 从图谱 2.1 中选择初始节点。
4. `node_content_loader` 抽取当前节点学习目标、必会点、常见误区和证据上下文。
5. Tutor 优先覆盖图谱 2.1 当前节点材料，并用图谱 2.2 / RAG 做补充证据增强。
6. 讲解后进入“课后停顿”：学习者可以直接追问或说卡点，也可以进入节点小测。
7. 临时追问走图谱 2.2 检索回答，回答后回到“继续追问 / 我懂了，进入小测”。
8. 节点后客观题批量测试，程序按 answer_key 确定性评分。
9. 未通过则错题讲解与变式题；通过则规划下一节点。
10. 用户选择继续下一节点或结束本轮学习并生成作业。
11. 二次登录/恢复时根据学生状态和作业状态分流。

注释说明：
这里的核心变化是“有状态的持续教学 + 图谱节点推进”，不是“每次从零开始的一问一答”。

## 三、三类知识图谱的使用说明

### 1）课程知识图谱（课程主线图）

作用：定义课程结构和学习路径。

在系统中的用法：

1. 测评后提供起点画像：概念差距会进入 `assessment_concept_gaps` 和初始 `user_knowledge_graph`。
2. 讲解前提供上下文：前置知识、学习目标、常见误区、相邻节点。
3. 卡点时做诊断：前置缺口检测，判断是否需要先补基础。
4. 讲完后定去向：给出继续当前、补前置、转相关节点等选项。

改进效果：

1. 教学顺序从“模型自由发挥”变为“按课程结构推进”。
2. 遇到卡点时能解释为什么卡住，并给出明确补救路径。

注释说明：
课程图谱负责“主线与路径”，不是资料仓库。

### 2）补充知识图谱（上传资料形成的证据层）

作用：补充课程主资料里没有覆盖的场景、案例和企业文档。

在系统中的用法：

1. 文件上传后自动解析、切块、向量化、建索引。
2. 检索时与课程主库并行召回。
3. 融合时课程主库优先，补充库用于补位。
4. 支持单文件删除和整库清空，索引和向量同步更新。

改进效果：

1. 回答不再只依赖课程主资料。
2. 对个性化资料和企业上下文更友好。

注释说明：
补充知识负责“证据增强”，不负责改变课程学习主线。

### 3）用户知识图谱 UKG（用户学情图）

作用：记录每个用户在每个知识点的学习状态原型，并为恢复、讲解策略和下一步推荐提供上下文。

数据结构（核心字段）：

1. status：not_started、in_progress、mastered、skipped。
2. turn_count：该节点互动轮次。
3. calibrated：测评校准分。
4. gap_type：概念缺口类型。
5. id：节点标识。

状态流转规则：

1. 测评后初始化为 not_started（带 calibrated）。
2. Tutor 进入节点时转为 in_progress，轮次递增。
3. 触发掌握标记并通过门控校验后转为 mastered。
4. 用户或策略跳过时转为 skipped。

更新触发点：

1. 测评完成后初始化 UKG。
2. Tutor 每轮讲解写入当前节点状态。
3. 隐藏教学标记触发掌握/跳过更新。
4. 下一步决策读取 UKG 做路径推荐。

前端与恢复机制：

1. 通过 user_knowledge_graph.sync 同步全量或增量状态。
2. 通过 graph.node_update 同步当前节点变化。
3. 历史恢复时重建 UKG 相关事件，恢复学习状态而非仅聊天文本。

改进效果：

1. 系统知道用户“已经会什么、还不会什么、下一步该补什么”。
2. 同一用户跨轮次、跨会话可以连续学习。

注释说明：
UKG 是个性化教学的核心方向，但当前仍是轻量原型。生产级伴学画像还需要把测验、临时追问、作业、错因和情绪信号统一沉淀为节点级证据事件，并统一掌握分尺度。

## 四、向量库详细使用说明

### 1）库结构

当前使用双库策略：

1. course_primary：课程主资料库。
2. supplemental：用户上传资料库。

两者独立建库、独立索引、统一融合。

### 2）入库流程

1. 解析文件内容（PDF、Markdown、文本等）。
2. 切分为文档块并附加 metadata。
3. 写入对应向量集合。
4. 更新知识索引与 BM25 缓存。

注释说明：
课程主库长期稳定，补充库高频增删，设计上必须分离。

### 3）检索流程

1. 先解析图谱锚点，建立图谱上下文。
2. 优先在 course_primary 召回当前节点与相关节点证据。
3. 同步在 supplemental 召回补充证据。
4. 执行混合融合：向量召回 + BM25 + 元数据匹配。
5. 进行重排与去重，生成可引用证据清单。
6. 若本地证据不足且开关开启，触发外部搜索补证据。

注释说明：
检索不是“只看向量相似度”，而是“图谱优先 + 混合召回 + 证据可引用”。

### 4）资料管理接口

1. 列表：/api/knowledge/files
2. 上传：/api/upload
3. 删除单文件：/api/knowledge/files/{filename}
4. 清空补充库：/api/knowledge/files（DELETE）

注释说明：
这些接口只管理补充库，不会破坏课程主库。

## 五、端到端运行流程（带 UKG 与向量库）

1. 用户输入主题，系统做主题识别与确认。
2. 进入对话式测评，输出概念差距。
3. 初始化 UKG，确定图谱锚点。
4. Tutor 发起检索：图谱锚点驱动，课程主库优先，补充库补位。
5. 返回证据、图谱上下文、推荐下一步信息。
6. Tutor 按证据讲解，并同步更新 UKG 与图谱节点状态。
7. 系统基于 UKG 和图谱关系做下一步推荐。
8. 前端通过事件实时渲染状态；会话恢复时可回到原学习进度。

## 六、已完成改进项详细解释

### 改进 1：学习流程从单轮问答升级为状态机闭环

1. 做了什么：补齐 flow_status、assessment_state、pending_interaction 等流程状态。
2. 为什么做：避免每轮对话丢上下文。
3. 结果：能连续推进，不会反复从头开始。

### 改进 2：课程图谱从展示层升级为决策层

1. 做了什么：图谱锚点、前置缺口、后继路径、盲区检测进入决策。
2. 为什么做：把教学顺序和补救路径结构化。
3. 结果：系统可以解释“为什么下一步这样走”。

### 改进 3：UKG 从测评结果升级为持续演化学情图

1. 做了什么：定义 UKG 字段、状态流转和事件同步，并接入 `StudentStateStore` 的节点、题目尝试和作业记录。
2. 为什么做：让系统能跨会话知道用户学到哪里、哪些节点未过、是否有作业未完成。
3. 结果：系统具备个性化教学的状态底座；但它仍是轻量学习记录，不应表述为完整生产级长期学习者模型。

### 改进 4：检索从单一召回升级为双库混合检索

1. 做了什么：course_primary + supplemental 双库，混合召回与重排。
2. 为什么做：同时保证主线正确性和场景覆盖度。
3. 结果：回答更稳、更贴题、可追溯证据更完整。

### 改进 5：会话恢复从文本恢复升级为学习状态恢复

1. 做了什么：恢复 UKG、图谱节点、测评状态、等待输入状态。
2. 为什么做：学习产品核心是“接着学”，不是“接着聊”。
3. 结果：中断后能无缝回到原学习阶段。

### 改进 6：临时追问从流程按钮升级为自然卡点表达

1. 做了什么：`post_lesson_choice` 支持“继续追问 / 我懂了，进入小测”，并允许直接输入一句卡点；`interruption_tutor` 的回答 prompt 改为按问题复杂度自适应，不固定套模板。
2. 为什么做：学习者遇到卡点时通常会直接说“不太明白这里”，不应被迫先理解系统按钮。
3. 结果：临时追问更像自然伴学对话，回答后仍能回到主线小测。

### 改进 7：GraphRAG 证据从调试直出升级为学习证据卡片

1. 做了什么：公式、图表、表格证据改为卡片展示；raw asset id、长 hash、raw LaTeX、raw HTML table 默认隐藏；图表支持真实缩略图与缺图占位。
2. 为什么做：证据应该帮助理解，而不是把检索调试结果塞进聊天气泡。
3. 结果：临时追问回答的主阅读流更干净，证据可追溯但不抢占教学解释。

### 改进 8：历史恢复从“回到聊天”升级为“回到当前学习动作”

1. 做了什么：恢复历史时同步顶部学习主题、当前图谱节点和等待状态；当前待处理卡片会在长公式、图片、表格布局稳定后自动进入可视区。
2. 为什么做：深度伴学用户恢复历史时关心的是“现在该做什么”，不是重新从历史开头翻到当前状态。
3. 结果：恢复 `awaiting_post_lesson_choice` 这类状态时，用户能直接看到“课后停顿”卡片，底部交流框不遮挡当前操作。

### 改进 9：公式图表从“材料堆叠”升级为“解释绑定 + 限量补充”

1. 做了什么：正文明确引用的公式、图表、表格绑定在对应解释段落附近；未被正文引用的补充媒体最多展示 3 张，并对旧历史 HTML 做前端去重限量。
2. 为什么做：学习者需要先读解释，再看对应材料；把检索到的所有媒体堆到回答底部会造成重复和注意力分散。
3. 结果：临时问答里公式、图表和表格的插入顺序更清晰，宽表格/长公式仍留在局部滚动容器内。

### 改进 10：错题本从“记录列表”升级为“按节点复习入口”

1. 做了什么：新增错题本 API 与前端弹窗，按知识节点分组展示错题，默认突出待复习题，支持“全部 / 待复习 / 已掌握”筛选、展开讲解、标记已掌握和取消掌握。
2. 为什么做：错题只有回到知识节点、错因和复习动作中才有学习价值，不能只是堆一串做错记录。
3. 结果：学习者可以先处理未掌握错题，再查看已掌握题；系统也能把错题掌握状态写回 `StudentState.wrong_question_book`。

当前边界：还没有“复习本节点”和“再做一遍原题”，排序控件也只在后端具备参数，前端仍需继续补齐。

### 改进 11：题目答疑从聊天插话升级为独立解题工作区

1. 做了什么：新增题目答疑 API 与前端弹窗，支持粘贴文字题、上传图片题、选择快速解答/深度解析/图片题专用模式，并保留历史记录。
2. 为什么做：用户常常会在主学习流之外遇到独立题目，直接塞进聊天主线会打断节点学习状态。
3. 结果：题目答疑可以独立完成一次解题，并把记录写入 `StudentState.question_help_records`；当前记录不会自动进入错题本。

当前边界：答疑是一次请求返回完整结果，不是真 token 流式；图片识别、模型不可用和是否一键加入错题本还需要后续规则。

### 改进 12：客观题复盘从“对错结果”升级为“逐题订正结构”

1. 做了什么：客观题选项改为整行可读布局；提交后每题展示本题解析、掌握状态、判断依据、所选项问题、常见误区和下一步动作。
2. 为什么做：只告诉用户“错了/对了”不足以形成订正，学习者需要知道自己按错了哪个判断条件。
3. 结果：节点小测后的复盘更适合直接进入错题讲解、变式题或错题本复习。

### 改进 13：公式显示从原始文本升级为本地 Markdown/KaTeX 渲染

1. 做了什么：前端加载本地 `marked` 与 `katex` vendor 文件，`ui.js` 暴露 `app.renderMarkdownContent` 和 `app.renderMath`，题目答疑、学习内容、复盘解释复用同一套 sanitizer 与公式渲染。
2. 为什么做：题目解答中大量使用公式，原始 LaTeX 或转义文本会直接破坏阅读体验。
3. 结果：行内公式和行间公式能在主要学习区域稳定渲染，同时仍保持 HTML allowlist 安全边界。
