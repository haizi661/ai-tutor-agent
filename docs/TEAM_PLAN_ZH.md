# 协作分工与推进方向（建议版）

## 1. 团队分工（按工作流拆分）

### A 组：后端编排与稳定性（Owner: 后端）

职责：

1. 维护 `core/`、`nodes/`、`orchestration/` 的一致性。
2. 管理路由策略、评分阈值、状态结构演进。
3. 保证节点输入输出契约稳定，避免接口层破坏业务逻辑。

交付物：

1. 节点行为单测与回归测试。
2. 路由策略版本记录。
3. 状态结构变更说明（兼容性文档）。

### B 组：API 与实时通信（Owner: 服务端）

职责：

1. 在 `interfaces/api/` 落地 FastAPI。
2. 对接 `CallbackEventSink` 与 `interfaces/sse.py`。
3. 提供会话创建、续学、流式事件订阅接口。

交付物：

1. `/health`、`/sessions`、`/sessions/{id}/stream` 等端点。
2. SSE/WebSocket 示例客户端。
3. API 文档与错误码规范。

### C 组：RAG 与知识增强（Owner: 算法/检索）

职责：

1. 在 `infrastructure/` 增加检索模块（向量库 + 文档切分 + 召回）。
2. 把检索结果注入 Tutor 节点 prompt。
3. 做检索质量评估（召回率、答案稳定性、幻觉率）。

交付物：

1. 文档索引构建脚本。
2. 检索服务接口（可供节点调用）。
3. 基准评估报告（有/无 RAG 对比）。

### D 组：前端体验与学习画像（Owner: 前端）

职责：

1. 接入流式事件并渲染会话界面。
2. 消费评分结构生成雷达图/趋势图。
3. 建立会话管理、重连与断点恢复体验。

交付物：

1. 聊天与评分可视化页面。
2. 事件到 UI 状态的映射层。
3. 关键页面测试（移动端/桌面端）。

### E 组：质量与运维（Owner: QA/平台）

职责：

1. 建立 CI（lint + tests）。
2. 维护依赖安全、环境配置、发布流程。
3. 制定 PR 审查规范和合并门禁。

交付物：

1. GitHub Actions 工作流。
2. 发布与回滚说明。
3. 质量看板（测试通过率、回归问题）。

## 2. 推进方向（建议里程碑）

### M1（1 周）：接口可用

目标：

1. API 层可发起会话并流式返回事件。
2. CLI 与 API 共用同一套会话用例。

### M2（1-2 周）：知识增强

目标：

1. Tutor 支持 RAG 检索增强。
2. 给出首版检索质量指标。

### M3（1 周）：前端打通

目标：

1. 前端可实时显示讲解、题目、评分和路由决策。
2. 雷达图渲染评分维度。

### M4（持续）：质量闭环

目标：

1. 建立 CI 门禁与 PR 模板。
2. 完成多模型评估与成本监控。

## 3. 协作规则（最小集）

1. 新功能优先走分层路径，不直接改兼容层。
2. 每个 PR 只做一类改动（例如仅 API 或仅 RAG）。
3. PR 必须附带测试结果和回归影响说明。
4. 涉及状态结构变更时，必须更新文档并给出迁移方案。
